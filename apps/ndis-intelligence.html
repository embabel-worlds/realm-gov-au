The register, read.

Five saved queries over the NDIS Commission's own compliance register and providers' own ACNC filings. Every figure is a published number or arithmetic over published numbers. Nothing here is an allegation about any provider — each tab says what its numbers can and cannot support.

How it works

1. The data

Two published sources, read by this realm (gov-au) when a view runs:

  • NDIS compliance register extracts: the Commission publishes dated extracts of its current register on data.gov.au. NdisSnapshot -[:HAS_ACTION]-> SnapshotAction reads one extract by its key datasetId|resourceId|filename (producer ndisActionsSnapshotRows, file kept seven days, answers cached one day).
  • Charity filings: ACNC Annual Information Statements for FY2024 and FY2023 (IntegrityQuery -[:HAS_AIS]-> AisReturn, -[:HAS_AIS_PRIOR]-> AisPriorReturn) for the charities that declared a program in the classification (ProgramClass -[:HAS_PROGRAM]-> CharityProgram). Published files on data.gov.au, kept up to seven days and answered from a one-day cache; the screens ask for {ai: {fresh: true}} on the program and FY2024 reads, which skips that one-day cache.

The register views read the extract named by their default snapshotKey parameters (06.07.2026, and 04.06.2026 as the older side of the diff). This app passes no arguments, so every view runs with its defaults.

2. The questions

One saved view per tab, run only when its Run button is pressed (runner.view(name, {})).

NdisNewEnforcement (view) — Actions present in one dated extract and absent from an earlier one — enforcement that APPEARED, which no single extract shows. An appearance is dated to the interval between two extracts, not to a day: the register's own effective date frequently precedes publication by months, and a row appearing now may concern conduct years old.

Parameters: newerSnapshot = '4ad8bb94-1982-43ff-a030-d6587b9aa460|8a6ce1fc-8f92-44ad-9c9d-2290dab7ee4f|ndis-commission-compliance-actions-06.07.2026.csv', olderSnapshot = '5087fd94-96e4-44a6-af20-e6c8177a4bca|7478346e-1fd9-4e9c-9487-b8e64ec608dd|ndis-commission-compliance-actions-04.06.2026.csv'. Run with defaults.

MATCH (o:NdisSnapshot {snapshotKey: $olderSnapshot})-[:HAS_ACTION]->(b:SnapshotAction)
WITH collect(b.register + '|' + toLower(b.name) + '|' + substring(coalesce(b.dateFrom, ''), 0, 10)) AS priorIds
MATCH (n:NdisSnapshot {snapshotKey: $newerSnapshot})-[:HAS_ACTION]->(a:SnapshotAction)
WHERE NOT (a.register + '|' + toLower(a.name) + '|' + substring(coalesce(a.dateFrom, ''), 0, 10)) IN priorIds
RETURN a.register AS actionType, a.name AS subject, a.abn AS abn, a.state AS state,
       substring(coalesce(a.dateFrom, ''), 0, 10) AS effectiveFrom,
       substring(coalesce(a.dateTo, ''), 0, 10) AS publishedUntil,
       CASE WHEN a.detail CONTAINS 'on the basis that'
              OR a.detail CONTAINS 'reasonably believes'
              OR a.detail CONTAINS 'convicted of'
              OR a.detail CONTAINS 'identified conduct' THEN true ELSE false END AS statesABasis,
       CASE WHEN a.detail CONTAINS 'section 73J' THEN 'audit obligation (s73J)'
            WHEN a.detail CONTAINS 'Worker Screening' THEN 'worker screening'
            WHEN a.detail CONTAINS 'Code of Conduct' THEN 'code of conduct'
            WHEN a.detail CONTAINS 'Incident Management' THEN 'incident management'
            WHEN a.detail CONTAINS 'Behaviour Support' OR a.detail CONTAINS 'Restrictive' THEN 'behaviour support / restrictive practices'
            ELSE 'not cited' END AS instrumentCited,
       substring(coalesce(a.detail, ''), 0, 400) AS commissionNarrative
ORDER BY actionType, effectiveFrom DESC
NdisEnforcementWaves (view) — Compliance notices grouped by the day they took effect. The register is not a stream of individual findings: notices arrive in mass batches on single dates, so a provider's presence in it may mean only that it sat inside one.

Parameters: snapshotKey = '4ad8bb94-1982-43ff-a030-d6587b9aa460|8a6ce1fc-8f92-44ad-9c9d-2290dab7ee4f|ndis-commission-compliance-actions-06.07.2026.csv', minNotices = 20. Run with defaults.

MATCH (n:NdisSnapshot {snapshotKey: $snapshotKey})-[:HAS_ACTION]->(a:SnapshotAction)
WHERE a.register CONTAINS 'Compliance notice'
WITH substring(a.dateFrom, 0, 10) AS effectiveDay, count(*) AS notices,
     sum(CASE WHEN a.detail CONTAINS 'section 73J' THEN 1 ELSE 0 END) AS citingAuditObligation
WHERE notices >= $minNotices
RETURN effectiveDay, notices, citingAuditObligation
ORDER BY notices DESC
NdisRegisterOpacity (view) — How specifically the register explains itself, per action type: how many rows state a basis ("on the basis that…", "reasonably believes", "convicted of") versus only describing what is prohibited or required. Banning orders publish scope, not conduct — this counts it.

Parameters: snapshotKey = '4ad8bb94-1982-43ff-a030-d6587b9aa460|8a6ce1fc-8f92-44ad-9c9d-2290dab7ee4f|ndis-commission-compliance-actions-06.07.2026.csv'. Run with defaults.

MATCH (n:NdisSnapshot {snapshotKey: $snapshotKey})-[:HAS_ACTION]->(a:SnapshotAction)
WITH a.register AS actionType, count(*) AS rows,
     sum(CASE WHEN a.detail CONTAINS 'on the basis that'
                OR a.detail CONTAINS 'reasonably believes'
                OR a.detail CONTAINS 'convicted of'
                OR a.detail CONTAINS 'identified conduct'
              THEN 1 ELSE 0 END) AS statingABasis,
     sum(CASE WHEN toLower(a.detail) CONTAINS 'criminal' THEN 1 ELSE 0 END) AS citingCriminalHistory,
     sum(CASE WHEN toLower(a.detail) CONTAINS 'falsif' OR toLower(a.detail) CONTAINS 'fraud'
              THEN 1 ELSE 0 END) AS citingFraudOrFalsification
RETURN actionType, rows, statingABasis,
       round(toFloat(statingABasis) / rows * 100) AS statingABasisPct,
       citingCriminalHistory, citingFraudOrFalsification
ORDER BY rows DESC
NdisWorkforceFlip (view) — Providers whose employee expenses collapsed as a share of service revenue between FY23 and FY24 while revenue held or grew — the work is now done by someone other than employees. Lawful, and the documented precondition of both sham contracting and billing intermediation.

Parameters: classification = 'Disability services', minService = 1000000. Run with defaults.

MATCH (p:ProgramClass {classification: $classification})-[:HAS_PROGRAM {ai: {fresh: true}}]->(g:CharityProgram)
WITH g.abn AS abn, head(collect(g.registrationStatus)) AS registrationStatus
MATCH (q:IntegrityQuery {abn: abn})-[:HAS_AIS {ai: {fresh: true}}]->(now:AisReturn)
MATCH (q)-[:HAS_AIS_PRIOR]->(prior:AisPriorReturn)
WITH abn, registrationStatus, now, prior,
     coalesce(toFloat(now.revenueGovernment), 0.0) + coalesce(toFloat(now.revenueGoodsServices), 0.0) AS svcNow,
     coalesce(toFloat(prior.revenueGovernment), 0.0) + coalesce(toFloat(prior.revenueGoodsServices), 0.0) AS svcPrior,
     coalesce(toFloat(now.employeeExpenses), 0.0) AS empNow,
     coalesce(toFloat(prior.employeeExpenses), 0.0) AS empPrior
WHERE toLower(coalesce(now.consolidated, 'n')) <> 'y'
  AND svcNow >= $minService AND svcPrior > 0
  AND empPrior / svcPrior >= 0.5
  AND empNow / svcNow < 0.3
RETURN now.charityName AS provider, abn, registrationStatus,
       svcPrior AS serviceRevenueFy23, svcNow AS serviceRevenueFy24,
       empPrior AS employeeExpensesFy23, empNow AS employeeExpensesFy24,
       round(empPrior / svcPrior * 100) AS labourShareFy23Pct,
       round(empNow / svcNow * 100) AS labourShareFy24Pct,
       prior.fteTotal AS fteFy23, now.fteTotal AS fteFy24,
       coalesce(toFloat(now.otherExpenses), 0.0) AS otherExpensesFy24,
       now.relatedPartyTransactions AS relatedPartyDeclared,
       now.reportingPeriodTo AS reportingPeriodTo
ORDER BY serviceRevenueFy24 DESC
NdisMoneyLeavesUnspecified (view) — Providers where most money leaves as unspecified "all other expenses" rather than wages or named grants — the brokerage / plan-management shape. Lawful and common, and the one place where public money's ultimate recipient is named in no public register.

Parameters: classification = 'Disability services', minService = 2000000, minOtherShare = 80. Run with defaults.

MATCH (p:ProgramClass {classification: $classification})-[:HAS_PROGRAM {ai: {fresh: true}}]->(g:CharityProgram)
WITH g.abn AS abn, head(collect(g.registrationStatus)) AS registrationStatus
MATCH (q:IntegrityQuery {abn: abn})-[:HAS_AIS {ai: {fresh: true}}]->(a:AisReturn)
WITH abn, registrationStatus, a,
     coalesce(toFloat(a.revenueGovernment), 0.0) + coalesce(toFloat(a.revenueGoodsServices), 0.0) AS svc,
     coalesce(toFloat(a.otherExpenses), 0.0) AS other,
     coalesce(toFloat(a.expensesTotal), 0.0) AS expenses,
     coalesce(toFloat(a.employeeExpenses), 0.0) AS emp
WHERE toLower(coalesce(a.consolidated, 'n')) <> 'y'
  AND svc >= $minService AND expenses > 0
  AND other / expenses * 100 >= $minOtherShare
  AND emp / svc < 0.35
RETURN a.charityName AS provider, abn, registrationStatus,
       svc AS serviceRevenueFy24, other AS otherExpensesFy24, expenses AS totalExpensesFy24,
       round(other / expenses * 100) AS otherExpensesSharePct,
       emp AS employeeExpensesFy24, a.fteTotal AS fteFy24,
       a.relatedPartyTransactions AS relatedPartyDeclared
ORDER BY serviceRevenueFy24 DESC

3. When it looks wrong

  • "No rows" is an answer: the shape is absent from the data the view read, not a failure.
  • The register tabs read fixed dated extracts (the defaults above). A newer extract is not read until those defaults change, so "What appeared" is the difference between those two extracts only.
  • If a source was capped or unavailable the result is PARTIAL and the page says so; treat counts as floors. Errors show in the operation panel with a retry.
  • Every screen finds a shape in self-reported or published numbers. Contracting, brokerage, restructures, closures and keying errors produce the same shapes lawfully.

4. What made this possible

  • Each tab is a saved Cypher view over files the Commission and the ACNC publish; nothing is loaded into a database first, and the page has no backend of its own.
  • The filing screens start from program rows and use each row's ABN to seed the next fetch (MATCH (q:IntegrityQuery {abn: abn})), so only those charities' filings are read.
  • "What appeared" is a set difference between two extracts written as one query: the older extract's identities are collected, then excluded from the newer.
