How it works

1. The data

Every tab reads the AusTender OCDS contract feed through this realm (gov-au). The publication window (PublicationWindow -[:PUBLISHED]-> ContractRelease, producer releasesPublishedInWindow) and the change window (ChangeWindow -[:CHANGED]-> ContractRelease, producer releasesModifiedInWindow) are fetched live when a lens asks for them, one UTC day at a time (up to 366 days, 12 pages of 100 releases per day), and cached for one hour. So a result is "as of the last fetch of that day, at most an hour ago". Concentration also reads ProcurementCategory, the UNSPSC titles seeded from the realm's reference data. Nothing is stored by the app; the From/To dates (To is exclusive) become the window key from/to in ISO instants.

2. The questions

Each tab runs one lens, only when its button is pressed. The lens runs the Cypher below through the knowledge graph, then does its grouping and arithmetic in the lens script, and returns a headline, rows and its coverage limits.

au-concentration (lens) — top-supplier share of value per agency and per UNSPSC category family; groups with fewer than three contracts are excluded.

Lens au-concentration, run through the app runtime (runner.lens). Arguments: from, to. $window is from/to.

Window releases

MATCH (w:PublicationWindow {window:$window})-[:PUBLISHED]->(r:ContractRelease)
RETURN r.supplierName AS supplierName, r.agencyName AS agencyName,
       toFloat(r.amount) AS amount, r.unspscCodes AS unspscCodes

Category titles

MATCH (c:ProcurementCategory) RETURN c.code AS code, c.title AS title
au-evergreen (lens) — contracts amended in the change window whose observed end date moved outward.

Lens au-evergreen, run through the app runtime (runner.lens). Arguments: from, to, minAmount = 500000 (set by this app).

Change-window releases

MATCH (w:ChangeWindow {window:$window})-[:CHANGED]->(r:ContractRelease)
WHERE toFloat(r.amount) >= $minAmount
RETURN r.cnId AS cnId, r.awardId AS awardId, r.tags AS tags, r.releaseDate AS releaseDate,
       r.supplierName AS supplierName, r.agencyName AS agencyName,
       toFloat(r.amount) AS amount, r.startDate AS startDate, r.endDate AS endDate,
       r.dateSigned AS dateSigned
au-threshold-clusters (lens) — agency–supplier pairs with several awards in the 60–100% band of the threshold that together exceed it.

Lens au-threshold-clusters, run through the app runtime (runner.lens). Arguments: from, to, threshold = 80000 (set by this app); $nearFloor is 60% of the threshold.

Near-threshold releases

MATCH (w:PublicationWindow {window:$window})-[:PUBLISHED]->(r:ContractRelease)
WHERE toFloat(r.amount) >= $nearFloor AND toFloat(r.amount) < $threshold
RETURN r.cnId AS cnId, r.awardId AS awardId, r.supplierName AS supplierName, r.agencyName AS agencyName,
       toFloat(r.amount) AS amount, r.releaseDate AS releaseDate,
       r.procurementMethod AS procurementMethod, r.description AS description
au-year-end-rush (lens) — June's committed value per agency against that agency's May, from two complete months.

Lens au-year-end-rush, run through the app runtime (runner.lens). Argument: year only (the From/To dates are not used). The query runs once for May and once for June, each month as one window.

One month of releases

MATCH (w:PublicationWindow {window:$window})-[:PUBLISHED]->(r:ContractRelease)
RETURN r.agencyName AS agencyName, toFloat(r.amount) AS amount

3. When it looks wrong

  • A headline of 0 with no rows means the window held no releases of that shape: no group with three or more contracts, no amendment that moved an end date, no cluster. It is an answer about the window, not a failure.
  • If a fetch was capped or a day failed, the lens reports status PARTIAL and the app shows "This result is partial" above the result; open "Coverage and interpretation limits" before using a total or share.
  • An error, or a timeout (the runner waits up to 15 minutes), shows in the operation panel with a retry; nothing is shown as an empty result in that case.
  • Wide windows are slow the first time (each day is a separate fetch) and fast for the next hour from cache. June timing reads two whole months and can take several minutes.
  • Extensions reads the modified feed, which filters on last-modified: a later amendment moves a release out of an older change window.

4. What made this possible

  • There is no copy of AusTender here. Matching a window node to its releases makes the appliance call the feed for that window, day by day, and cache each day; the lens sees ordinary graph rows.
  • The page has no backend of its own: it names a lens and its arguments, and the appliance runs it, tracks it as an operation the page can follow and retry, and returns the result.
